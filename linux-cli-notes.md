## 1. Before touching anything

First thing on any new terminal, glance at the prompt:

```bash
whoami
hostname
pwd
```

Sounds obvious, but it has saved many engineers from running destructive commands on the wrong box:
- On **Amazon Linux 2023** (our AWS EC2 instance), you will see: `[ec2-user@ip-172-31-x-x ~]$`
- On **Ubuntu**, you will see: `ubuntu@ip-172-31-x-x:~$`
- On macOS / local shells: `username@hostname:directory$`

Also, before pasting in any script—especially one generated by an LLM—inspect the environment:

```bash
cat /etc/os-release
bash --version
uname -a
```

Knowing your Linux distribution is essential because default users, package managers, and file paths differ across environments:
- **Amazon Linux 2023 (AL2023)**: Fedora-based. Default user is `ec2-user`, package manager is `dnf` (or `yum` in Amazon Linux 2), home directory is `/home/ec2-user`.
- **Ubuntu / Debian**: Debian-based. Default user is `ubuntu` (or `admin`), package manager is `apt`, home directory is `/home/ubuntu`.
- **RHEL / CentOS**: Default user is `ec2-user` or `centos`, package manager is `dnf` / `yum`.

Both Ubuntu and Amazon Linux 2023 ship modern Bash (5.x), but scripts written on macOS default to Bash 3.2, and scripts with hardcoded paths like `/home/ubuntu` will fail immediately on Amazon Linux. Always inspect `/etc/os-release` first so you don't spend time debugging the wrong issue.

## 2. Moving around and managing files

### Path Navigation (Never Hardcode Home Paths)

```bash
pwd
ls -la
cd ~/data_pipeline                  # relative to current user's home (portable across all distros)
cd "$HOME/data_pipeline"            # environment variable expansion (best practice for scripts)
cd /home/$(whoami)/data_pipeline   # dynamically evaluated full path
cd ../scripts                       # relative navigation
cd -                                # back to wherever you just were
```

> [!TIP]
> **Why avoid hardcoding `/home/ubuntu`?**
> A command like `cd /home/ubuntu/data_pipeline` will fail with `No such file or directory` on Amazon Linux because the default user is `ec2-user` (`/home/ec2-user`). Using `~` or `$HOME` automatically resolves to the correct path on Amazon Linux, Ubuntu, Red Hat, or any future instance you create.

`ls -la` over plain `ls` — the `-a` flag reveals hidden dotfiles like `.env`, `.bashrc`, and `.git`, which hold credentials and configurations.

### Setting up a working folder

```bash
# Set up a structured workspace in the user's home directory
mkdir -p ~/data_pipeline/{raw,staged,scripts,logs}
cd ~/data_pipeline
touch config.yaml
```

The `-p` flag creates parent directories as needed and does not error if the directory already exists—always safe to use.

### File operations: copy, move, and remove

Remember: `mv` deletes the source file upon moving, while `cp` preserves it.

```bash
cp scripts/extract.py scripts/extract.py.bak
mv extract.py ./scripts/
rm -f old_test_file.txt
rm -rf ./staged/obsolete_test/       # force recursive deletion — no undo, verify path first
rmdir ./empty_folder/                 # safe deletion — fails if directory contains files
```

Before running `rm -rf` on any directory, run `ls` on that exact path first. It takes two seconds and prevents accidental data loss.

### Batch moves with wildcards and counts

When processing incoming data drops:

```bash
# Move and copy batch files using wildcards
mv sample-data/data/incoming/*.csv ./staged/
cp sample-data/logs/*.log ./logs_backup/

# Sanity check: count matching files before running bulk operations
ls sample-data/data/incoming/*.csv | wc -l
```

### Finding files with `find`

For time- or size-based filtering that `ls` cannot handle:

```bash
find ./logs -name "*.json" -mtime -1                # modified in the last 24 hours
find sample-data/data/incoming -name "*.csv" -mtime -1
find /var/log -type f -size +10M                   # files larger than 10 MB
find ./logs -name "*.tmp" -mtime +7 -exec rm {} \;  # older than 7 days
```

> [!WARNING]
> Before running `find ... -exec rm {} \;`, always run the command without `-exec` first to verify which files will be targeted.

## 3. Reading, searching, and stitching commands together

### Inspecting file contents

```bash
head -5 sample-data/data/incoming/orders_part1.csv   # inspect header and delimiter
tail -20 sample-data/logs/syslog
less sample-data/logs/access.log                    # navigate with '/' to search, 'q' to quit
tail -f sample-data/logs/agent_memory.log           # live stream new log entries (Ctrl+C to exit)
```

Running `head -n 5` on a CSV file before loading it into a database or pipeline verifies delimiter consistency, headers, and quote escaping.

### Searching with `grep`

Extract specific patterns from logs:

```bash
grep "Out of memory" sample-data/logs/syslog
grep -i "error" sample-data/logs/agent_memory.log         # case-insensitive
grep -c "Action:" sample-data/logs/agent_memory.log        # count occurrences only
grep -A 5 "Traceback" sample-data/logs/agent_memory.log    # 5 lines after match (stack traces)
grep -B 2 -A 10 "ERROR" sample-data/logs/agent_memory.log  # 2 lines before, 10 lines after
grep -E "50[0-9]" sample-data/logs/access.log              # regex match for HTTP 5xx errors
```

### Parsing columns with `awk`

Once lines are filtered, `awk` isolates specific fields:

```bash
# Extract status code ($9) and response size ($10) from space-delimited access logs
awk '{print $9, $10}' sample-data/logs/access.log

# Rank status codes by frequency
awk '{print $9}' sample-data/logs/access.log | sort | uniq -c | sort -nr

# Parse comma-separated files (-F',')
awk -F',' '{print $1, $5}' sample-data/data/incoming/orders_part1.csv

# Condition-based extraction: URLs ($7) for all 5xx status codes ($9)
awk '$9 ~ /^5/ {print $7}' sample-data/logs/access.log
```

### In-place editing with `sed`

Search and replace strings across config files or data dumps:

```bash
# Preview replacement without modifying the file
sed 's/dev_db/prod_db/g' sample-data/config.yaml

# Modify file in place while creating a safety backup (.bak)
sed -i.bak 's/dev_db/prod_db/g' sample-data/config.yaml

# Clean NULL tokens from raw CSV files
sed -i 's/NULL//g' sample-data/data/incoming/orders_part1.csv
```

Always run `sed` without `-i` first to verify the substitution pattern against stdout, then apply `-i.bak` to keep a rollback copy.

### Pipes and stream redirection

Linux tools are designed to do one job well and link together via pipes (`|`):

```bash
# Find OOM events and write to summary file
cat sample-data/logs/syslog | grep "Out of memory" > oom_summary.txt

# Count how many OOM events involved python
grep "python3" oom_summary.txt | wc -l

# Identify the top 5 most frequently requested endpoints
cat sample-data/logs/access.log | awk '{print $7}' | sort | uniq -c | sort -nr | head -n 5
```

**Redirection operators:**
- `>` Overwrite standard output to a file
- `>>` Append standard output to a file
- `<` Feed file content into standard input
- `2>` Redirect standard error (stderr)
- `&>` Redirect both stdout and stderr
- `|` Pipe stdout of left command to stdin of right command

### Archiving and compression with `tar`

```bash
# Compress a directory into a tarball
tar -czvf artifact.tar.gz ./sample-data/

# Inspect archive contents without extracting (always do this first)
tar -tzvf artifact.tar.gz

# Extract into a specific destination directory
tar -xzvf artifact.tar.gz -C ./restored/
```

## 4. Permissions, processes, SSH, and cloud operations

### File permissions & portable ownership

```bash
# Check existing permissions
ls -l sample-data/dummy-key.pem

# Lock down SSH private keys (owner read-only, group/others none)
chmod 400 sample-data/dummy-key.pem

# Make deployment and ETL scripts executable
chmod +x scripts/stage_data.sh
chmod 750 scripts/stage_data.sh

# Universal ownership: dynamically assigns current user and primary group
chown $(whoami):$(id -gn) config.yaml
```

> [!IMPORTANT]
> **Avoid hardcoding `chown ubuntu:ubuntu`!**
> On Amazon Linux, `ubuntu` does not exist; running `chown ubuntu:ubuntu` produces `chown: invalid user: ‘ubuntu:ubuntu’`.
> Using `chown $(whoami):$(id -gn) file` works dynamically across Amazon Linux (`ec2-user:ec2-user`), Ubuntu (`ubuntu:ubuntu`), and any other environment.

**Permission string breakdown (`-rwxr-xr--`):**
- Character 1: File type (`-` regular file, `d` directory, `l` symlink)
- Characters 2-4: Owner permissions (`rwx` = 4 + 2 + 1 = 7)
- Characters 5-7: Group permissions (`r-x` = 4 + 0 + 1 = 5)
- Characters 8-10: Others permissions (`r--` = 4 + 0 + 0 = 4)

### Securing SSH keys on Windows vs Linux/macOS

SSH clients will reject private keys with loose permissions:
- **On Linux / macOS / WSL**:
  ```bash
  chmod 400 MyDemoKey.pem
  ```
- **On Windows (PowerShell)**:
  `chmod` does not natively exist in Windows PowerShell. Use `icacls` to restrict file access exclusively to your Windows user:
  ```powershell
  # Remove inherited permissions and grant read-only access to current user
  icacls MyDemoKey.pem /inheritance:r /grant:r "$($env:USERNAME):R"
  ```

### Connecting to EC2 via SSH (Dynamic & Non-Hardcoded)

When launching EC2 instances, avoid relying on hardcoded IP addresses or assuming a single username.

#### Method 1: Environment variables

```bash
# Define connection parameters dynamically
KEY_PATH="MyDemoKey.pem"           # path to private key
EC2_USER="ec2-user"                # ec2-user (Amazon Linux/RHEL) or ubuntu (Ubuntu)
EC2_IP="<instance-public-ip>"      # paste your current instance IP or DNS

ssh -i "$KEY_PATH" "$EC2_USER@$EC2_IP"
```

#### Method 2: Automatic lookup via AWS CLI

If AWS CLI is configured on your local machine, retrieve the running instance's IP dynamically:

```bash
# In Bash:
EC2_IP=$(aws ec2 describe-instances \
  --filters "Name=instance-state-name,Values=running" \
  --query "Reservations[0].Instances[0].PublicIpAddress" \
  --output text)

ssh -i "$KEY_PATH" "ec2-user@$EC2_IP"
```

```powershell
# In Windows PowerShell:
$EC2_IP = (aws ec2 describe-instances `
  --filters "Name=instance-state-name,Values=running" `
  --query "Reservations[0].Instances[0].PublicIpAddress" `
  --output text)

ssh -i MyDemoKey.pem "ec2-user@$EC2_IP"
```

#### Method 3: SSH configuration shortcut (`~/.ssh/config`)

To connect with a simple `ssh ec2-demo` without remembering IPs or flags, add this block to your local `~/.ssh/config`:

```ssh-config
Host ec2-demo
    HostName <instance-public-ip>
    User ec2-user
    IdentityFile /path/to/MyDemoKey.pem
```

#### Default SSH usernames reference

| Cloud AMI / Distro | Default SSH User | Package Manager |
|---|---|---|
| **Amazon Linux 2023 / AL2** | `ec2-user` | `dnf` / `yum` |
| **Ubuntu Server** | `ubuntu` | `apt` |
| **Debian** | `admin` or `debian` | `apt` |
| **Red Hat Enterprise Linux (RHEL)** | `ec2-user` | `dnf` / `yum` |
| **CentOS** | `centos` or `ec2-user` | `yum` / `dnf` |
| **Fedora** | `fedora` or `ec2-user` | `dnf` |

### Copying files between local machine and EC2 (`scp`)

To transfer sample data, scripts, or backups to and from your EC2 instance:

```bash
# Copy a local directory to EC2 home directory
scp -i "$KEY_PATH" -r sample-data "$EC2_USER@$EC2_IP:~/"

# Copy a zip file to EC2
scp -i "$KEY_PATH" sample-data.zip "$EC2_USER@$EC2_IP:~/"

# Download a remote file from EC2 back to your local machine
scp -i "$KEY_PATH" "$EC2_USER@$EC2_IP:~/data_pipeline/logs/etl.log" ./local_logs/
```

### Self-discovery inside EC2 via IMDSv2

Scripts running inside an EC2 instance can discover their own public IP, private IP, and instance ID without any hardcoding using AWS Instance Metadata Service (IMDSv2):

```bash
# 1. Fetch an IMDSv2 session token (valid for 6 hours)
TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")

# 2. Query instance attributes dynamically
INSTANCE_ID=$(curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id)
PUBLIC_IP=$(curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/public-ipv4)
LOCAL_IP=$(curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/local-ipv4)
AZ=$(curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/placement/availability-zone)

echo "Running on $INSTANCE_ID ($PUBLIC_IP) in $AZ"
```

### Package managers across distributions

When installing utilities like `htop`, use the command corresponding to the active distribution:

```bash
# Amazon Linux 2023 (Fedora family)
sudo dnf install -y htop unzip

# Amazon Linux 2 / RHEL 7 / CentOS 7 (Yum)
# sudo yum install -y htop unzip

# Ubuntu / Debian (APT)
# sudo apt update && sudo apt install -y htop unzip
```

### Environment variables

Keep credentials out of code and terminal history:

```bash
export OPENAI_API_KEY="sk-..."
env | grep API_KEY
python3 my_langchain_script.py
unset OPENAI_API_KEY
```

### Process inspection and resource monitoring

```bash
ps aux | grep python          # list running python processes
top                           # interactive resource monitor (press 'q' to quit)
htop                          # enhanced visual monitor (install via dnf/apt)
kill <PID>                    # SIGTERM (graceful shutdown request)
kill -9 <PID>                 # SIGKILL (force termination if process hangs)
```

### Storage and memory utilization

Check available capacity before executing data-heavy jobs:

```bash
df -h                         # disk space per mounted volume
du -sh ~/data_pipeline/       # human-readable folder size
du -sh ./* | sort -rh | head  # top disk consumers in current directory
free -h                       # available RAM and swap space
```

### Managing background services (`systemd`)

Amazon Linux 2023 and modern Ubuntu both use `systemd` for service management:

```bash
systemctl status docker
sudo systemctl restart nginx
journalctl -u docker.service --since "1 hour ago"   # service logs from the past hour
journalctl -u docker.service -f                    # follow live service logs
```

To configure Docker on Amazon Linux 2023:

```bash
sudo dnf install -y docker
sudo systemctl start docker
sudo systemctl enable docker
sudo usermod -aG docker $(whoami)   # allow non-root docker usage (re-login to apply)
```

## 5. Getting reliable scripts from an LLM

LLMs produce fragile code when asked vague questions. To obtain production-ready scripts, supply:
1. **Target persona & environment**: Specify the exact Linux distribution (e.g., Amazon Linux 2023 with Bash 5.2 and DNF, or Ubuntu 24.04 with APT).
2. **Explicit constraints**: Mandate dynamic paths (`$HOME`, `$PWD`), variable quoting, error handling (`set -euo pipefail`), and portable commands.
3. **Expected output format**: Require raw script output without extraneous commentary.

### Example A: Debugging a pipeline archive error

**Input file**: `sample-data/logs/jenkins_console_snippet.log`

```bash
cat sample-data/logs/jenkins_console_snippet.log
```

**Prompt**:

```text
Act as a Senior DevOps Engineer. I am encountering a failure in a Jenkins pipeline executing a Bash script on an Amazon Linux 2023 instance (Kernel 6.1, Bash 5.2). Below is the extracted log block. The script attempts to compress a directory and push it to AWS S3, but it fails with "tar: exit delayed from previous errors".

1. Identify the root cause from the logs.
2. Provide the corrected CLI command.
3. Explain how to use grep and awk to proactively detect this error condition in future pipeline runs.

[paste sample-data/logs/jenkins_console_snippet.log here]
```

*What to verify in the response*: The prompt should identify that `tar` failed because a file (`model_weights.bin`) was actively being modified during compression (file changed as we read it)—a concurrency issue, not an S3 permissions problem.

### Example B: Portable ETL data cleaning script

**Input files**: `sample-data/data/incoming/*.csv`

**Prompt**:

```text
Write a production-grade Bash script for an ETL preprocessing pipeline with the following requirements:
- Environment: Amazon Linux 2023 and modern Linux distros (Bash 5.x).
- Accept the input directory and output directory as CLI arguments ($1 and $2), defaulting to "$HOME/data_pipeline/raw" and "$HOME/data_pipeline/staged". Do NOT hardcode user paths like /home/ubuntu.
- Find all .csv files modified in the last 24 hours within the input directory.
- Use sed to replace all occurrences of the literal string 'NULL' with an empty string in each matching file.
- Move processed files to the output directory with an ISO-8601 timestamp suffix in the filename.
- Log all operations with timestamps to a log file inside "$HOME/data_pipeline/logs/etl_staging.log".
- Handle edge cases: missing directories, zero matching files, and write permissions.

Output only the executable Bash script with comments.
```

*What to verify in the response*:
- Uses `find ... -mtime -1` instead of `ls`.
- Properly quotes all variable expansions (`"$input_dir"`) to handle spaces in filenames.
- Uses dynamic paths (`$HOME` or positional arguments) rather than hardcoded `/home/ubuntu`.
- Validates directories before running file operations.

**Testing the generated script**:

```bash
mkdir -p ~/data_pipeline/{raw,staged,logs}
cp sample-data/data/incoming/*.csv ~/data_pipeline/raw/
bash your_generated_script.sh ~/data_pipeline/raw ~/data_pipeline/staged
```

### Example C: Analyzing LangChain / Agent logs

**Input file**: `sample-data/logs/agent_memory.log`

**Prompt**:

```text
I have a log file named agent_memory.log containing mixed LangChain reasoning logs, tool outputs, and Python tracebacks.

Provide a single, portable Linux command pipeline (using grep, awk, sort, uniq) that:
1. Filters only lines containing the pattern "Action: "
2. Extracts the tool name following "Action: "
3. Counts occurrences of each unique tool
4. Sorts output in descending order of frequency

Do not provide a Python script; provide the native Bash pipeline.
```

**Executing the pipeline**:

```bash
grep "Action:" sample-data/logs/agent_memory.log | awk -F"Action: " '{print $2}' | sort | uniq -c | sort -nr
```

## 6. Quick reference cheat sheet

| Task | Portable / Best Practice Command | Notes |
|---|---|---|
| Current user & group | `whoami && id -gn` | Avoid assuming `ubuntu` or `ec2-user` |
| Current working directory | `pwd` | Displays resolved absolute path |
| Portable home directory | `cd ~` or `cd "$HOME"` | Works across all distros |
| List all files + permissions | `ls -la` | Shows hidden files and permissions |
| Recent file search | `find <dir> -name "*.csv" -mtime -1` | Modified in last 24 hours |
| Recursive search in files | `grep -rn "pattern" <dir>` | Line number (`-n`) and recursive (`-r`) |
| Filter & extract columns | `awk -F',' '{print $1, $3}' file.csv` | Set custom delimiter with `-F` |
| In-place edit with rollback | `sed -i.bak 's/old/new/g' file` | Creates `file.bak` as backup |
| Frequency ranking | `sort \| uniq -c \| sort -nr` | Standard pipeline for log metrics |
| Lock private key (Linux/Mac) | `chmod 400 <key.pem>` | Owner read-only |
| Lock private key (Win PS) | `icacls <key.pem> /inheritance:r /grant:r "$($env:USERNAME):R"` | Windows-native ACL restriction |
| Dynamic file ownership | `chown $(whoami):$(id -gn) <file>` | Automatically detects user and group |
| Package install (AL2023) | `sudo dnf install -y <pkg>` | Amazon Linux 2023 / Fedora |
| Package install (Ubuntu) | `sudo apt update && sudo apt install -y <pkg>` | Debian / Ubuntu |
| Connect to EC2 | `ssh -i <key.pem> <user>@<public-ip>` | `ec2-user` for AL2023, `ubuntu` for Ubuntu |
| EC2 Metadata (IMDSv2) | `curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/...` | Inside instance: dynamic IP/ID |
| Copy files to EC2 | `scp -i <key.pem> -r <source> <user>@<ip>:~/` | Remote copy over SSH |
| Process monitoring | `ps aux \| grep <name>` or `htop` | Process table and live monitor |
| Graceful vs forced kill | `kill <PID>` then `kill -9 <PID>` | Try SIGTERM before SIGKILL |
| Storage & memory status | `df -h && free -h` | Human-readable units |
| Service status & logs | `systemctl status <svc> && journalctl -u <svc> -f` | Standard systemd commands |

## 7. Sample data & quick setup

The repository includes a self-contained `sample-data/` suite (also available as `sample-data.zip`) designed for hands-on practice without exposing production assets:

- `sample-data/logs/syslog`: Linux system log containing Out-of-Memory (OOM) killer events.
- `sample-data/logs/access.log`: Nginx access log containing 1,000 HTTP requests with varied status codes (200, 301, 404, 500, 502).
- `sample-data/logs/agent_memory.log`: Agent execution log containing LangChain `Action:`/`Observation:` traces and Python stack traces.
- `sample-data/logs/jenkins_console_snippet.log`: CI/CD failure snippet demonstrating `tar: exit delayed from previous errors`.
- `sample-data/data/incoming/orders_part[1-3].csv`: Simulated sales records containing `NULL` placeholders for sanitization exercises.
- `sample-data/config.yaml`: Service configuration file with `dev_db` endpoints for regex replacement practice.
- `sample-data/dummy-key.pem`: Safe placeholder key for testing `chmod 400` permission rules locally.

### Fast setup on a newly created EC2 instance

To set up any newly launched EC2 instance for this walkthrough:

```bash
# 1. From your local machine: upload sample data
scp -i MyDemoKey.pem sample-data.zip ec2-user@<instance-public-ip>:~/

# 2. Connect to the EC2 instance
ssh -i MyDemoKey.pem ec2-user@<instance-public-ip>

# 3. Inside the EC2 terminal: install unzip and extract files
sudo dnf install -y unzip
unzip sample-data.zip
ls -la ~/sample-data/
```
